citegraph

A folder of academic PDFs goes in. A deduplicated, queryable citation graph comes out — papers, references, edges, and canonical authors — with a cost gate before any LLM call and a checkpoint after every stage.

235 tests passing CI green tagged v0.1.0 not on PyPI yet
01 · What it does

Five CSVs from a pile of PDFs

citegraph converts each PDF to markdown locally with docling, asks Google Gemini for the paper’s own metadata and its full reference list, fuzzy-deduplicates the references across the corpus, optionally enriches them with CrossRef / OpenAlex records, and clusters author names into canonical people. Every stage is cached on disk, so an interrupted run resumes instead of re-paying.

papers.csvOne row per source paper, with a stable p- id.
references.csvOne row per cited work after dedup, indexed by r- id.
citation_graph.csvThe edges: citing_id → cited_id.
authors.csvOne row per canonical author (a- id), deduplicated across the corpus.
author_citations.csvEvery author occurrence, with back-pointers to record, position, and citing paper.

The checked-in sample run (out/) shows the shape at small scale: 7 papers → 239 citation events → 229 canonical references → 340 canonical authors.

02 · The pipeline

Six checkpointed stages

Each stage reads the previous stage’s artifacts from --out and writes its own. Run them one at a time for quality control, or all at once with citegraph run. Click a stage to see what it does, what it writes, and what can go wrong. Stages marked LLM call Gemini; everything else runs on your machine.

PDF → markdown, on your machine

citegraph convert ./pdfs --out ./out --recursive --ocr-auto

Docling converts each PDF to markdown/<stem>.md. Re-runs skip files that already exist. --recursive walks subdirectories and folds the relative path into the cache stem so same-named PDFs don’t clobber each other; a collision check raises before docling ever runs. --ocr-auto converts normally first, then re-runs only image-only outputs through EasyOCR; --ocr forces full-page OCR everywhere.

After every pass a quality check flags markdown with fewer than 200 substantive characters and writes conversion_warnings.json. Inspect it before paying for extraction — scanned PDFs that skipped OCR are the usual culprit.

Writesmarkdown/*.md, conversion_warnings.json
Requirescitegraph[pdf] extra (docling)
Knobs--recursive · --ocr-auto · --ocr

Markdown → paper metadata

citegraph metadata --out ./out --llm-concurrency 4

Each markdown file goes to Gemini with PaperMetadata as a structured-output schema; results cache as metadata/<stem>.json and roll up into papers.csv. Papers are processed concurrently (default 4) while output order and per-paper failure isolation are preserved: one bad PDF becomes a row in metadata_failures.jsonl, not a crashed run, and is retried next time because no cache was written.

Afterwards a fuzzy pass compares the source papers to each other and writes source_duplicates.json when two differently-named PDFs contain the same paper.

Writespapers.csv, metadata/*.json
Warningsmetadata_failures.jsonl, source_duplicates.json
Knobs--model · --llm-concurrency

Markdown → reference lists

citegraph references --out ./out --llm-concurrency 4

Three safeguards wrap the extraction. Before sending, the markdown is sliced to its bibliography section (falling back to the full file when no header matches). If the response hits the output-token cap, it retries once at 2× the cap. And an inline-citation estimate over the body logs a warning when Gemini returned fewer than half the references the text appears to cite.

Papers that process successfully but return zero references land in papers_no_references.json — usually an image-only PDF that needed --ocr-auto. The CLI prints a fresh cost estimate and asks for confirmation first; --yes skips the prompt.

Writesreferences_raw.csv, references/*.json
Warningsreferences_failures.jsonl, papers_no_references.json
Knobs--model · --llm-concurrency · --yes

Fuzzy dedup → canonical references + edges

citegraph dedup --out ./out

References cluster under a weighted rapidfuzz score over title, authors, and journal, plus a year window. A reference cited with a year in one paper still merges with the same work cited without a year elsewhere — missing years are treated as unknown, not as a mismatch — but genuinely unparseable year data fails closed and keeps records apart. The first row in each cluster names it, which is what keeps r- ids deterministic across runs.

Writesreferences.csv, citation_graph.csv
Knobs--threshold · --title-weight · --authors-weight · --journal-weight · --year-window
Costnone — fully local

Optional: CrossRef → OpenAlex enrichment

citegraph enrich --out ./out --enrich-contact "you@example.com" --enrich-max-workers 2

Each deduplicated reference is looked up on CrossRef first, then OpenAlex. Candidates are scored by fuzzy title similarity minus a penalty when both years are known and disagree; both raw and adjusted scores are kept so rejected matches can be audited. Transient 429/503/timeout failures retry with backoff. Every row carries explicit diagnostics (enrichment_status, miss reason, scores, year delta), and OpenAlex author ids + ORCIDs ride along as the authors stage’s strongest identity signal.

Responses cache per-reference under enrichment/, so re-runs are cheap. Use a real contact email and modest worker count to stay in the providers’ good graces.

Writesenriched_references.csv, enrichment_summary.json, enrichment_misses.csv
Requirescitegraph[crossref] or [all] (httpx)
Knobs--enrich-threshold · --enrich-year-penalty · --enrich-retry-attempts · --enrich-timeout · --enrich-max-workers

Author normalization → canonical people

citegraph authors --out ./out --merge-mode strict

Every author string in the corpus — “Cárdenas, J.-C.”, “Juan-Camilo Cardenas” — is parsed into surname / given names / initials, blocked by diacritic-stripped surname, and clustered precision-first: full-name records anchor clusters, and an initial-only record joins one only when exactly one anchor matches (or co-author overlap disambiguates). External OpenAlex / ORCID ids from enrichment override string evidence entirely. --merge-mode loose collapses by surname + first initial instead when recall matters more.

Low-confidence clusters are flagged in author_review.json. Your corrections go in author_aliases.csv (cluster_id,canonical_id) and are applied last — a rerun of this stage is cheap and local.

Writesauthors.csv, author_citations.csv, author_review.json
Knobs--merge-mode strict|loose · --aliases
Costnone — fully local

Three utilities sit beside the stages: citegraph estimate prices the two LLM stages without making a single API call, citegraph status reports which artifacts exist in an output directory, and citegraph report writes a self-contained report.html QC dashboard into the out directory — stage progress, a problems summary, a per-paper drill-down, dedup / enrichment / author audits, and an artifact integrity check. Re-run it after any stage.

03 · How to use it

Staged when you care, one-shot when you don’t

Install with the PDF extra and set a Gemini key (GOOGLE_API_KEY in the environment or a local .env). For a new corpus, prefer the staged path: it gives you an inspection point after every externally fragile step.

pip install "citegraph[all]"        # pdf conversion + enrichment
export GOOGLE_API_KEY="your-key-here"

The recommended loop for a fresh corpus. Stop and inspect after each command; every warning sidecar that is absent means that check was clean.

citegraph convert "$PDF_DIR" --out "$OUT_DIR" --recursive --ocr-auto
#   inspect markdown/ and conversion_warnings.json

citegraph estimate --out "$OUT_DIR"          # tokens + USD, no API calls
citegraph metadata --out "$OUT_DIR"          # then review papers.csv
citegraph references --out "$OUT_DIR"        # prompts before spending
citegraph dedup --out "$OUT_DIR"
citegraph enrich --out "$OUT_DIR" --enrich-contact "you@example.com"
citegraph authors --out "$OUT_DIR"
citegraph status --out "$OUT_DIR"

From a repo checkout, scripts/smoke_test.sh runs this exact sequence with sensible defaults.

Runs conversion, prints the cost estimate, and waits for your confirmation before any LLM call. --yes skips the prompt for CI.

citegraph run ./pdfs --out ./out --ocr-auto --enrich

The full run also writes run_summary.json (row and warning counts, model, config) and artifact_manifest.json (version, artifact paths, configuration) for provenance.

The library mirrors the CLI exactly: every Pipeline stage method accepts its input explicitly or loads it from out_dir. Missing upstream artifacts raise StageNotReadyError with a hint at the prior step.

from citegraph import Pipeline

pipe = Pipeline(pdf_dir="./pdfs", out_dir="./out", enrich=True)
print(pipe.estimate_extraction_cost().format_summary())
result = pipe.run()

result.papers        # DataFrame, id as column
result.references    # DataFrame, indexed by id
result.graph         # (citing_id, cited_id) edges
result.authors       # canonical people

Tuning objects — DedupConfig, EnrichConfig, AuthorClusterConfig — pass straight into Pipeline(...); the README documents every field.

Six CSVs, a handful of review sidecars, and per-stage caches that are safe to inspect and safe to delete (deleting forces re-extraction). IDs are deterministic slugs — p-doe-2020-some-title — so re-runs and hand-curated overrides stay stable.

05 · Querying the graph

CitationGraph: the read-only view

Load a finished run from disk and traverse it without touching the reviewed CSVs. Author-level methods unlock automatically when the author tables exist (has_authors); calling them without raises a RuntimeError that tells you what to run.

from citegraph import CitationGraph

g = CitationGraph.from_out_dir("./out")   # or .from_pipeline_result(result)
g.top_cited(10)[["Title", "Year", "citation_count"]]

06 · Costs & privacy

What it spends, and what leaves your machine

Only two stages cost money, and both sit behind an estimate-and-confirm gate. citegraph estimate walks the converted markdown, skips already-cached files, and prices the remaining work without any API call. Pricing constants carry an as-of date (2026-09-04) — check them against Google’s published rates before trusting a budget.

stageservicedata sent externally
convertdocling, localnothing (docling may download model files)
metadataGoogle Geminia bounded portion of the converted paper text
referencesGoogle Geminithe detected bibliography section — or the full markdown when no section header is found
deduplocalnothing
enrichCrossRef, OpenAlexextracted titles, authors, and query parameters
authorslocalnothing

Don’t process confidential or embargoed documents until sending their text to these services has been approved. The full privacy discussion lives in docs/USER_GUIDE.md §7.

07 · Gaps & next steps

Where it is honest to say “not yet”

The engine is in strong beta shape: 235 tests pass, CI is green on Python 3.11–3.13, the wheel builds, and v0.1.0 is tagged. What remains is mostly proof and polish, not functionality.

blocking
The v0.1.0 publish to PyPI failed — the package is not installable yet.

The tag fired the workflow, but PyPI rejected it because the trusted publisher is not registered. Fix: on pypi.org, add a pending publisher for project citegraph (owner yabramuvdi, workflow publish.yml, environment pypi), then re-run the failed workflow. Until then, every pip install citegraph in the docs fails.

blocking
Scientific validity is not yet demonstrated.

The evaluation harness works, but its gold standard is a single synthetic paper — the reported 100% scores only prove the wiring. The credibility task for a research tool: hand-label ~5 real papers (~150 references, including dedup pairs and author-identity cases), run evaluation/evaluate.py, and publish the numbers in evaluation/RESULTS.md.

inherent
Four stages are probabilistic and need a human in the loop.

LLM extraction can misread, fuzzy dedup can over- or under-merge, enrichment can pick the wrong record, and initial-only author names are sometimes genuinely ambiguous. The review hooks exist — warning sidecars, enrichment diagnostics, author_review.json, author_aliases.csv — but the review itself is manual CSV-and-JSON work. No interactive review workflow exists yet.

planned
No user interface — by decision, for now.

docs/UI_ARCHITECTURE.md records the plan: keep the Python engine independent and build a local-first app (job service + browser frontend) beside it, with a hosted service explicitly out of scope for the first milestone. Nothing of it is implemented.

planned
Trust documents for a public release are missing.

No CHANGELOG.md, CITATION.cff, CONTRIBUTING.md, or generated API reference. Privacy and limitations are now covered by the user guide; these remaining pieces matter mainly at the moment the package goes public.

chronic
Two tables drift by nature.

The Gemini pricing constants in cost_estimation.py and the heuristic token estimates are dated snapshots — both carry an as-of date and should be re-checked at each release rather than trusted as ground truth.
